# Synthetic evidence fixtures

These images were generated specifically for this demonstration. They do not depict a real shopper, order, warehouse incident, carrier label, serial number, or merchant product.

| File | Intended evidence role |
| --- | --- |
| `outbound-two-cameras.png` | Outbound reference showing two cameras and two cables |
| `return-empty-box.png` | Inbound inspection showing an empty two-unit tray |
| `return-wrong-item.png` | Inbound inspection showing a low-value mouse instead of the expected cameras |
| `return-imitation.png` | Inbound inspection showing one visually inconsistent device and one missing unit |
| `return-label-rma-8821.png` | Privacy-safe carton and return-label capture for RMA/order/tracking extraction |
| `catalog-juniper-arc-one.png` | Original catalog reference for the fictional two-camera kit |
| `return-quantity-mismatch.png` | Inbound inspection showing one camera and an empty second cavity |
| `return-damaged-product.png` | Inbound inspection showing both cameras with one visibly damaged unit |
| `return-matching-contents.png` | Inbound inspection showing the complete, undamaged two-camera kit |

The five added fixtures were created with OpenAI's built-in image-generation tool. The manifest records checksums for the generated assets, and lookup identifiers remain structured metadata rather than relying on OCR alone.

The UI must label every fixture as synthetic. Model output is an evidence assessment, not proof of intent or authorization for an adverse decision.
