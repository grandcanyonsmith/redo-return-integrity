# Synthetic evidence fixtures

These images were generated specifically for this demonstration. They do not depict a real shopper, order, warehouse incident, carrier label, or SKIMS product. Garment styling follows the publicly described SKIMS apparel line so the demo reads as apparel rather than electronics; nothing here comes from SKIMS.

| File | Intended evidence role |
| --- | --- |
| `catalog-fits-everybody-bodysuit.png` | Catalog reference for the two-piece cami bodysuit order |
| `warehouse-label-station.png` | Fulfilment-centre label print station used as facility context |
| `outbound-two-bodysuits.png` | Outbound reference showing both polybagged pieces going into the mailer |
| `return-label-rma-8821.png` | Return-label capture for RMA/order/tracking extraction |
| `return-matching-contents.png` | Inbound inspection showing both pieces, tags and liners attached |
| `return-empty-box.png` | Inbound inspection showing a mailer holding only the packing slip |
| `return-wrong-item.png` | Inbound inspection showing an unbranded cotton tee in place of the order |
| `return-quantity-mismatch.png` | Inbound inspection showing one piece where two were authorized |
| `return-damaged-product.png` | Inbound inspection showing a snagged seam and a run in the knit |
| `return-wardrobing.png` | Inbound inspection showing wear, makeup transfer, and a safety-pinned tag |
| `return-imitation.png` | Side-by-side construction and care-label comparison against the reference |

Every fixture was created with an image-generation model. The manifest records checksums for the generated assets, and lookup identifiers remain structured metadata rather than relying on OCR alone.

The UI must label every fixture as synthetic. Model output is an evidence assessment, not proof of intent or authorization for an adverse decision.
