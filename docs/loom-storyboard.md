Target length: 7:45–8:30. Record only after the live URL passes the demo runbook. Use a clean browser profile, hide bookmarks/extensions/account identifiers, disable notifications, and never open AWS/OpenAI/Notion settings or developer tools containing secrets.

## 0:00–0:35 — thesis

**Screen:** landing hero.

**Say:**

> This is Redo Return Integrity, an evidence-led decision layer from checkout through appeal. I built it around one rule: uncertainty should create a solvable step, not an automatic accusation. The first deep fraud family is empty, decoy or wrong-item, possible imitation, and quantity mismatch. I’ll show the shopper, merchant, and warehouse experiences, then how I would prove value without counting abandoned challenges as fraud.

Point briefly to the three trust statements and the fictional SKIMS disclosure.

## 0:35–1:15 — product layers and fit

**Screen:** landing product-layer section.

**Say:**

> I would enter through Evidence & Observe: consistent photos, weights, native events, draft communications, and evidence-ready packets. That can save labor and generate better labels before we claim predictive lift. Predict & Decide becomes Pro only after shadow and controlled measurement. Managed Verify creates the strongest physical evidence in Redo-operated facilities. Protection remains a separate risk-transfer product; a payout is not fraud prevention.

Mention that Redo's public Returns, Verify, API, and Reclaim surfaces make this an adjacent proposal, not a replacement platform.

## 1:15–2:05 — the 15-checkpoint contract

**Screen:** lifecycle explorer; select checkout, reverse handoff, and inspection.

**Say:**

> There are fifteen evaluable checkpoints: visit and identity, checkout and order release, outbound pack and custody, delivery, return request and authorization, reverse handoff and transit, warehouse receipt and inspection, refund settlement, and appeal or recovery. Every checkpoint shows the same contract: native facts, deterministic signals, OpenAI assessment, merchant policy, accountable action, a shopper cure, and the next state. The snapshot prevents future warehouse facts from leaking into an earlier checkout evaluation.

Point to evidence tier, available timestamp, simulated/live label, policy/model version, and “human-only deny.”

## 2:05–2:55 — journey A: legitimate checkout step-up

**Screen:** shopper portal checkout path.

**Say:**

> This shopper has a narrow checkout uncertainty. Instead of blocking, the merchant offers the least intrusive step: bot check, payment authentication, a verified channel, an approved identity vendor, or human review. This public demo never collects government ID. Completion clears the order. Decline, abandonment, and technical failure are different states and none becomes a fraud label. A discount variant can test conversion and mature loss, but it only measures willingness to complete the flow—not honesty.

Complete the good-actor cure and show the order proceed.

## 2:55–3:50 — journey B: impossible reverse logistics

**Screen:** reverse logistics shopper case; select/add synthetic staffed receipt.

**Say:**

> Here, a carrier ingest event implies 620 miles in 18 minutes. Deterministic code owns that time-and-distance calculation. OpenAI explains the conflict but cannot invent a scan or deny the return. The shopper can supply a staffed drop-off receipt, authorize a trace, explain pickup, or request human review. When the receipt arrives, it is appended with provenance and a new evaluation supersedes the old one. Carrier error stays a live exculpatory explanation.

Show the decision changing without deleting the original timeline item.

## 3:50–5:25 — journey C: managed physical verification

**Screen:** operator workstation, then merchant console.

**Say:**

> At a managed facility, the operator scans the RMA and captures a neutral protocol: calibrated receipt weight, exterior and seal, opening sequence, all contents, quantity, and serial where appropriate. The operator does not see a “fraudster score.” Deterministic checks compare expected quantity, outbound versus return weight, SKU and serial. OpenAI vision returns structured observations with exact evidence references, uncertainty, missing views, and an abstention path.

Choose empty or quantity mismatch and run the assessment.

> The model can say that no expected item is visible or that a visual inconsistency needs review. It cannot determine criminal intent, and it cannot declare an item counterfeit from a photo. Merchant policy can hold, request evidence, partially approve, approve, or route to review. Only a human can issue a final denial.

In the merchant console, show source evidence, deterministic signal, model recommendation, policy result, and human action as separate cards.

## 5:25–6:20 — shopper contest, deadline, and Reclaim boundary

**Screen:** merchant decision/appeal timeline.

**Say:**

> The shopper sees the exact discrepancy, alternatives, owner, and deadline. They can explain a split package, carrier repackaging, merchant fulfillment error, or accidental wrong return, then add evidence or request a second review. New evidence can overturn the decision and correct settlement. If the case later becomes a real processor dispute, the system can prepare a source-linked packet. Evidence-ready is not submitted. Reclaim handoff happens only after an authorized inquiry, alert, or dispute, and submission, acknowledgement, outcome, and recovery are separate states.

Do not imply the prototype sends a message or processor evidence.

## 6:20–7:20 — measurement that can survive diligence

**Screen:** evaluation lab.

**Say:**

> The dashboard separates verified policy-ineligible value stopped, experimental estimated deterrence, unresolved exposure, actual recovery, protection payout, labor savings, and legitimate friction. It never calls non-verifiers fraud. Prevention is the randomized intention-to-treat difference in mature loss, reported beside good-actor conversion and margin cost. A case is attributed to the first effective checkpoint so the same dollars are not added fifteen times.

> The `$80 million` managed-warehouse and `$200 million` broader-surface figures are scenario inputs, not verified Redo revenue. If finance confirms the same GMV definition and subset relationship, the warehouse lane creates better physical labels for part of the surface; it does not justify multiplying a market fraud rate by Redo revenue. Warehouse and broad accuracy remain separate until a transport analysis holds.

Point to definitions/tooltip and illustrative badge.

## 7:20–8:05 — engineering and rollout

**Screen:** architecture view or GitHub README.

**Say:**

> The demo is strict TypeScript and React with an AWS Lambda/API Gateway backend, DynamoDB event and case projections, private S3 through CloudFront origin access control, short-lived uploads, and Secrets Manager for the OpenAI key. The Responses API uses structured output, image input where needed, `store:false`, point-in-time facts, and safe human-review fallback. CI typechecks, tests, builds, runs the browser journeys, and synthesizes CloudFormation without deploying.

> I would start with a four-to-six-week Evidence & Observe pilot, shadow for another four-to-six weeks, and run controlled interventions before Pro enforcement. First labor value can arrive in weeks; defensible paid prevention evidence is more realistically twelve to twenty weeks and depends on outcome maturity.

## 8:05–8:20 — close

**Screen:** landing or README four-link section.

**Say:**

> The repository, live prototype, full product specification, and this walkthrough are linked together. What I’m proposing is not a black-box fraud score. It is an accountable evidence system that can learn from Redo's operational advantage while preserving a fast path for good customers.

End without opening a Loom share/settings screen on camera.
